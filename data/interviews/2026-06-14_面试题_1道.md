## Q1: LLM输出非确定性的架构权衡与格式清洗

难度: Senior / Staff
领域: 生产化AI / Agent架构
场景: 今日在 ai-developer-knowledge-hub 管道中，我们发现 LLM 生成的文档格式极其不稳定（Markdown 代码块闭合错误、列表层级混乱、表格格式畸形），导致下游解析器频繁崩溃。你需要决定如何系统性解决这个问题。

题目:
你面临一个典型的生产环境两难选择：
1. 优化 System Prompt 和 Few-shot Examples 试图约束模型输出格式。
2. 构建一个确定性的后处理层对 LLM 输出进行清洗。

请解释为什么不能仅依赖 Prompt Engineering？如果选择构建后处理层，请设计 `MarkdownSanitizer` 的核心逻辑（Python），并说明如何优雅地处理“代码块闭合缺失”这种边界情况。同时，讨论将清洗逻辑嵌入 `daily_pipeline.py` 和嵌入具体的 Write Agent 内部的架构差异与选择依据。

答案要点:
1. 核心思路：承认 LLM 的概率生成本质，明确 Prompt 无法保证 100% 的格式确定性，必须引入非 AI 的确定性规则层作为守门员。
2. 具体方案：提供 Python 代码实现清洗逻辑，侧重于状态机处理代码块和表格。
3. 权衡分析：比较后处理层（维护成本高、可靠性高）与 Prompt 工程（维护成本低、可靠性低）的投入产出比。
4. 反面教训：展示如果清洗逻辑写得过于严格，可能会误伤正常的特殊内容。
5. 衡量指标：提及 downstream parsing error rate 的下降。

面试官会关注什么:
- 候选人是否深刻理解“LLM是非确定性函数”这一基本事实，而不是试图通过更强的 Prompt 来祈祷结果稳定。
- 处理边界情况时的代码鲁棒性，例如如何处理嵌套代码块或未闭合的反引号。
- 是否考虑了性能损耗，特别是流式输出场景下的处理难度。
- 可追问：如果清洗逻辑本身引入了 Bug（例如错误删除了关键内容），如何做版本回滚和监控？

```python
import re

class MarkdownSanitizer:
    """
    A deterministic post-processing layer to normalize LLM markdown output.
    Addresses issues like unclosed code fences and malformed lists.
    """

    def __init__(self):
        # Pattern to detect code blocks
        self.code_fence_pattern = re.compile(r'```(\w*)\n')

    def sanitize(self, raw_text: str) -> str:
        if not raw_text:
            return ""
        
        # 1. Fix unclosed code fences (Edge Case Handling)
        text = self._fix_code_fences(raw_text)
        
        # 2. Normalize headings (Ensure space after #)
        text = re.sub(r'^(#{1,6})([^\s#])', r'\1 \2', text, flags=re.MULTILINE)
        
        # 3. Clean up excessive blank lines
        text = re.sub(r'\n{3,}', '\n\n', text)
        
        return text

    def _fix_code_fences(self, text: str) -> str:
        """
    Ensures every code fence opening has a closing fence.
    This is a common failure mode in LLM generation.
    """
        lines = text.split('\n')
        stack = []
        output = []
        
        for line in lines:
            if line.startswith('```'):
                if not stack:
                    # Opening fence
                    stack.append(line)
                    output.append(line)
                else:
                    # Closing fence (or accidental nested open)
                    if line == stack[-1]:
                        stack.pop()
                    else:
                        # Treat as closing for the previously opened block anyway (Heuristic)
                        stack.pop()
                    output.append(line)
            else:
                output.append(line)
        
        # If stack is not empty, append closing fences
        while stack:
            output.append('```')
            stack.pop()
            
        return '\n'.join(output)

## Q1: 解决LLM生成内容非确定性格式的工程化方案

难度: Senior
领域: 生产化AI / Agent架构 / Prompt工程
场景: 在自动化内容生成Pipeline中，LLM输出的Markdown格式极其不稳定，经常出现代码块闭合不完整、表头缺失、列表层级错误等问题，导致下游发布平台（如微信、Dev.to）渲染失败。你需要设计一个可靠的后处理层来保证输出质量。

题目:
假设你正在负责一个文章生成Agent，LLM输出的Markdown无法通过Prompt完全修正（特别是代码块）。请设计一个Post-Processing架构，要求：
1. 能够检测并修复不完整的代码块；
2. 能够过滤掉LLM幻觉产生的“假”代码块（例如非代码内容被包裹在 ``` 中）；
3. 确保对LLM的推理延迟影响最小。

请给出具体的架构方案、核心代码逻辑（Python）以及如何处理极端的边界情况（如嵌套代码块）。

答案要点:
1. 核心思路：引入确定性Sanitizer层，与模型生成解耦，基于规则或小模型进行修复。
2. 具体方案：
   - 使用基于状态机的Markdown解析器检测闭合状态。
   - 对不闭合的 ``` 强制添加闭合标签。
   - 利用语法检测（如Pygments）识别假代码块并移除标记。
3. 权衡分析：增加了一层处理逻辑和少量延迟，但大幅提高了发布成功率；需权衡正则表达式 vs 专用解析库 的维护成本。
4. 反面教训：单纯依赖Prompt Engineering（如“请严格遵守Markdown语法”）无法100%解决随机性问题，不可信。
5. 衡量指标：发布失败率、Sanitizer层平均耗时、人工修复工时。

面试官会关注什么:
- 候选人是否意识到LLM的随机性本质，从而拒绝“调整Prompt直到解决”的 naive 方案。
- 是否考虑过性能影响（同步处理 vs 异步队列）。
- 是否提到具体的Markdown解析坑（如GFM与标准Markdown的差异）。

## Q2: 复杂Agent工作流中的工具调用失败恢复机制

难度: Staff
领域: Agent架构 / Tool Calling / 失败模式分析
场景: 你的Agent正在进行一项需要连续调用三个工具（搜索、代码执行、文章生成）的任务。在执行阶段，第二个工具（代码执行）因非代码语法错误（如依赖库缺失）偶发性失败，导致整个Pipeline崩溃。

题目:
请设计一个具备自愈能力的Agent执行层。当Tool Calling失败时，系统需满足以下约束：
1. 不能简单重试（如果代码逻辑本身错误，重试无效）；
2. 必须保持Context连续性，让LLM知道失败原因并尝试修正；
3. 需要防止陷入死循环（LLM不断尝试同样的错误代码）。

请提供核心的伪代码或类设计，展示如何管理Tool Execution的State和Feedback Loop。

答案要点:
1. 核心思路：引入Error Observation机制，将工具报错作为特殊Message反馈给LLM，并配合最大步数限制。
2. 具体方案（LangChain4j风格伪代码）：
   ```java
   public interface SelfHealingAgent {
       @UserMessage("Execute the task. Tools available: {tools}")
       String execute(@UserMessage String task);
   }
   
   // 执行循环逻辑
   while (step < MAX_STEPS) {
       ToolExecutionResult result = toolSpec.execute(arguments);
       if (result.isSuccess()) break;
       
       // 关键：将错误注入记忆
       memory.add(UserMessage.from(
           "Tool execution failed: " + result.getError() + ". Please fix the arguments or logic."
       ));
       step++;
   }
   ```
3. 权衡分析：自愈增加了Token消耗和Latency，但提升了复杂任务的成功率。
4. 反面教训：盲目重试会导致成本爆炸；完全忽视错误会导致Agent挂起。
5. 衡量指标：任务端到端成功率、平均自愈轮数、Token消耗增长率。

面试官会关注什么:
- 候选人是否区分了“可重试错误”（网络超时）和“不可重试错误”（逻辑错误）。
- 是否设计了退避策略或熔断机制。
- 对Memory Window的管理是否考虑到了错误信息挤占上下文的问题。
